# Регламент экстренного отката релиза DOCXдодыр (Rollback Procedure)

## 1. Назначение и контекст
Настоящий документ определяет пошаговую процедуру экстренного отзыва (Rollback) релизных пакетов или Release Candidate (RC) приложения «DOCXдодыр» в случае обнаружения критических дефектов уровня P0/P1 (нарушение изоляции персональных данных, сбои дешифратора, повреждение исходных документов, краш при запуске на чистых ОС).

---

## 2. Архитектурные гарантии безопасности при откате
Приложение спроектировано с полным физическим разделением исполняемых файлов и пользовательских данных (ADR 0002, ADR 0008):
- **Исполняемые файлы** приложения read-only (`/Applications/DOCXdodyr.app` на macOS, `%LOCALAPPDATA%\Programs\DOCXdodyr` на Windows).
- **Пользовательские данные, журналы и кэш** изолированы в системных каталогах `platformdirs`:
  - macOS: `~/Library/Application Support/DOCXdodyr`, `~/Library/Caches/DOCXdodyr`, `~/Library/Logs/DOCXdodyr`.
  - Windows: `%LOCALAPPDATA%\DOCXdodyr`, `%LOCALAPPDATA%\DOCXdodyr\Cache`, `%LOCALAPPDATA%\DOCXdodyr\Logs`.
- **Локальные дешифраторы (`дешифратор.json`)** сохраняются исключительно в выбранных пользователем каталогах документов и не затрагиваются обновлением или удалением исполняемых файлов.
- **Обратная совместимость состояний**: модуль `state_migration.py` гарантирует, что конфигурация пользователя (`settings.json`) и сохраненные сессии ревью (`review_queue.json`) корректно считываются даже при возврате на предыдущие версии приложения.

Благодаря этому замена бинарника или даунгрейд версии **никогда не приводит к потере настроек, ключей шифрования или повреждению пользовательских дешифраторов**.

## 3. Сценарии отката

### Сценарий A. Отзыв локального Release Candidate (до публичного релиза)
Если регрессия обнаружена на этапе валидации локального RC (до публикации в GitHub Releases):
1. **Очистка скомпилированных артефактов**:
   ```bash
   rm -rf dist/DOCXdodyr-*.dmg dist/DOCXdodyr-*.zip dist/DOCXdodyr-Setup-*.exe dist/SHA256SUMS.txt
   ```
2. **Локальный аудит состояния Git**:
   ```bash
   git status
   ```
3. **Устранение причины сбоя**: внесение точечного исправления в код, запуск регрессионных тестов:
   ```bash
   ./venv/bin/pytest tests/test_stage10_release_candidate.py -v
   ```
4. **Повторный запуск сборочного конвейера**:
   ```bash
   python scripts/package_release.py --package
   ```

---

### Сценарий B. Экстренный отзыв публичного релиза на GitHub Releases
Если версия уже опубликована в репозитории на GitHub, и в ней обнаружен блокирующий дефект:

1. **Немедленная деактивация релиза (Yank / Mark as Pre-release)**:
   Чтобы прекратить скачивание дефектной сборки новыми пользователями:
   ```bash
   # Пометить релиз как черновик / предварительный
   gh release edit v3.0.1 --prerelease
   ```
   Или полное удаление дефектных бинарных ассетов из релиза:
   ```bash
   gh release delete-asset v3.0.1 DOCXdodyr-3.0.1-arm64.dmg -y
   gh release delete-asset v3.0.1 DOCXdodyr-Setup-3.0.1-win64.exe -y
   gh release delete-asset v3.0.1 SHA256SUMS.txt -y
   ```

2. **Публикация предупреждения (Incident Notice)**:
   Отредактировать текст релиза `v3.0.1` на GitHub, добавив в начало предупреждение:
   ```markdown
   > [!CAUTION]
   > Релиз v3.0.1 временно отозван из-за обнаруженной проблемы (Issue #XX).
   > Пользователям рекомендуется использовать стабильную версию v2.2.0.
   ```

3. **Удаление или аннулирование Git-тега** (при необходимости):
   ```bash
   git tag -d v3.0.1
   git push --delete origin v3.0.1
   ```

### Сценарий C. Инструкция для пользователей по откату (Client Downgrade)
Пользователи, успевшие установить отозванную версию, могут выполнить мгновенный безопасный возврат:

#### Для пользователей macOS:
1. Скачать стабильный образ предыдущей версии (например, `DOCXdodyr-2.1.0-arm64.dmg`).
2. Открыть DMG-диск и перетащить значок `DOCXdodyr` в папку `Applications` (`Программы`).
3. При появлении системного диалога выбрать вариант **«Заменить» (Replace)**.
4. Все персональные настройки, сохраненные очереди и дешифраторы в `~/Library/Application Support/DOCXdodyr` сохраняются автоматически.

#### Для пользователей Windows:
1. Открыть *Параметры Windows* -> *Приложения и возможности*.
2. Найти в списке «DOCXдодыр» и нажать «Удалить» (удаляются только бинарники из `%LOCALAPPDATA%\Programs\DOCXdodyr`, пользовательский профиль в `%LOCALAPPDATA%\DOCXdodyr` не затрагивается).
3. Запустить установщик стабильной версии (например, `DOCXdodyr-Setup-2.1.0-win64.exe`).
4. Все пользовательские настройки и история дешифрования останутся на месте.

---

### Сценарий D. Выпуск ускоренного хотфикса (Hotfix Release)
После отзыва дефектной версии:
1. Создать изолированную ветку хотфикса:
   ```bash
   git checkout -b hotfix/2.2.1
   ```
2. Внести минимально необходимое точечное исправление.
3. Обновить версию до `2.2.1` в `version.py`, `assets/Info.plist`, `installer/DOCXdodyr.iss`, `sbom.json`.
4. Запустить полный регрессионный тест:
   ```bash
   ./venv/bin/pytest -ra
   ```
5. Пересобрать дистрибутивы, сгенерировать новые контрольные суммы и выпустить релиз `v2.2.1`:
   ```bash
   python scripts/package_release.py --package
   ```
