# ADR 0008: Политика обновлений приложения и технической поддержки

## Статус
Принято (Accepted) — 2026-09-03

## Контекст
Десктопные приложения требуют стратегии доставки исправлений и обновлений (patching) и организации обратной связи с пользователями. Реализация встроенных фоновых авто-апдейтеров (Sparkle / WinSparkle) требует поддержания серверной инфраструктуры (appcast feeds), раздачи тяжелых бинарников, организации самоперезаписи исполняемых файлов на машинах пользователей и строгой нотаризации/подписи, что может создавать ложные срабатывания антивирусов и проблемы в изолированных сетях.

## Решение
1. Для релиза DOCXдодыр 2.2 утверждена модель **ручного обновления через официальные GitHub Releases**:
   - Пользователь скачивает новую версию дистрибутива (.dmg или .exe) и устанавливает её поверх предыдущей.
   - Пользовательские конфигурации (`settings.json`), ключи в системном хранилище (`Keychain`/`Credential Manager`), локальные словари замен/исключений, скачанные модели и дешифраторы располагаются в платформенных пользовательских каталогах (`platformdirs.user_data_dir`), поэтому они гарантированно не затрагиваются и не удаляются при обновлении самого исполняемого пакета приложения.
2. В интерфейс (раздел «О программе») закладывается информационная ссылка на страницу релизов и возможность ручной проверки актуальности версии через открытый публичный GitHub Releases API (с graceful fallback при отсутствии сети).
3. Техническая поддержка, сбор багрепортов и предложений организуются через **GitHub Issues**:
   - Предоставляются структурированные шаблоны тикетов (Issue Templates), предупреждающие о недопустимости публикации конфиденциальных текстов документов, персональных данных или логов с путями к закрытым файлам.
4. Разработка полноценного бесшовного фонового сервиса автообновлений отложена на минорные релизы после оформления сертификатов подписи.

## Последствия
- Положительные: отсутствие необходимости поддерживать отдельную серверную инфраструктуру обновлений; полная предсказуемость для корпоративных пользователей; безопасность в изолированных контурах.
- Ограничения: необходимость ручной загрузки новых версий пользователем.
