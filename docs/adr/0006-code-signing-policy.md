# ADR 0006: Политика подписи кода и доверия операционных систем

## Статус
Принято (Accepted) — 2026-09-03

## Контекст
Публичный выпуск десктопного приложения на macOS и Windows сталкивается с механизмами защиты операционных систем (Apple Gatekeeper и Microsoft Defender SmartScreen). Официальная подпись требует платной ежегодной подписки Apple Developer Program ($99/год) и коммерческого сертификата Windows Authenticode (EV/OV, $200–400/год). Требовалось определить, является ли приобретение этих сертификатов обязательным условием для первого релиза v2.2.

## Решение
1. Разрабатываемые сборочные скрипты (PyInstaller, packaging scripts) проектируются с **полной поддержкой production-подписи**:
   - macOS: поддержка hardened runtime, entitlements, `codesign --deep --options runtime`, `notarytool submit` и `stapler staple`;
   - Windows: поддержка `signtool sign` с поддержкой сертификатов PFX/PKCS#12 и внешних timestamp серверов.
2. Для версии 2.2 платные платные сертификаты **не являются блокирующим требованием**:
   - Если секреты подписи отсутствуют в переменных окружения сборки, формируются корректные ad-hoc сборки: на macOS приложение подписывается локальным ключом (`codesign -s - --force --deep`), на Windows формируется стандартный инсталлятор без цифровой подписи.
   - В поставку, README и Release Notes включается понятное 1-шаговое руководство для пользователей по запуску (контекстное меню «Открыть» на macOS, «Подробнее» -> «Выполнить в любом случае» на Windows).
3. При появлении у проекта платных ключей подписи сборки смогут автоматически подписываться без изменения архитектуры приложения.

## Последствия
- Положительные: отсутствие финансовых и организационных задержек перед первым релизом; полная готовность сборочного пайплайна к интеграции ключей в будущем.
- Ограничения: пользователи столкнутся со стандартными предупреждениями безопасности ОС при первом открытии файла.
