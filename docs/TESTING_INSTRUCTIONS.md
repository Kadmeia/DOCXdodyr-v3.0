# Тестирование DOCXдодыр

Документ описывает быстрый автоматический прогон и ручной сценарий, который
повторяет действия пользователя. Основной набор использует локальные моки и
не скачивает Qwen. Отдельные тесты открывают настоящее окно WebView; они
запускаются только по явному запросу в интерактивной сессии с переменной
`DOCXDODYR_RUN_NATIVE_GUI=1`. Обезличивание и восстановление DOCX/XLSX
выполняются реальными функциями приложения.

## Автоматические тесты

Запускайте команды из корня проекта в окружении Python 3.11.x. Проверьте
версию через `python --version`; окружение другой версии нужно создать заново.
Все команды `python` ниже предполагают активированное окружение Python 3.11.

### macOS

Если виртуальное окружение уже создано:

```bash
./venv/bin/python -m pytest -q
```

Для нового окружения:

```bash
python3.11 -m venv venv
./venv/bin/python -m pip install -r requirements.txt -r requirements/requirements-dev.txt
./venv/bin/python -m pytest -q
```

### Windows PowerShell

Если используется готовое окружение:

```powershell
.\venv\Scripts\python.exe -m pytest -q
```

Для нового окружения:

```powershell
py -3.11 -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements/requirements-dev.txt
.\venv\Scripts\python.exe -m pytest -q
```

Ожидаемый результат — строка с количеством пройденных тестов и `0 failed`.
Для повторения только пользовательских сценариев:

```text
macOS:   ./venv/bin/python -m pytest -q tests/test_human_scenarios.py
Windows: .\venv\Scripts\python.exe -m pytest -q tests/test_human_scenarios.py
```

Дополнительные автономные прогоны точек входа (они используют временные
копии документов и не записывают результаты в каталог фикстур):

Сначала создайте синтетические входные документы командами
`python tests/create_test_files.py` и `python tests/generate_mock_data.py`.

```text
macOS:   ./venv/bin/python tests/run_auto_tests.py
         ./venv/bin/python tests/run_functional_tests.py
Windows: .\venv\Scripts\python.exe tests\run_auto_tests.py
         .\venv\Scripts\python.exe tests\run_functional_tests.py
```

В `tests/test_human_scenarios.py` проверяются:

1. запуск окна и фильтр файлового диалога;
2. выбор папки и передача корня в пакетный обработчик, включая каталог
   `Обезличенные документы`;
3. сохранение настроек, выбор документов для восстановления и вызовы UI;
4. пакет DOCX + XLSX с одинаковым ID сущности и общим дешифратором;
5. сохранение метки таблицы и восстановление обеих таблиц/документов;
6. безопасный Qwen-постпроцесс: модели передаётся только обезличенный текст,
   плейсхолдеры сохраняют порядок, а отсутствие локальной модели даёт no-op.

Тесты в `tests/test_qwen_postprocessor.py`, `tests/test_batch_entity_ids.py` и
`tests/test_table_entity_context.py` дополняют сценарный прогон проверками
порядка токенов, падежных форм и координат ячеек.

## Ручная проверка UI

Ручная проверка нужна для фактического WebView и системного диалога выбора
файлов; автоматические тесты этого не требуют.

1. Создайте копии нескольких небольших DOCX/XLSX с тестовыми данными. Не
   используйте реальные персональные данные. Удобно начать с файлов в
   `tests/source_files/` после запуска `python tests/generate_mock_data.py`.
2. Запустите приложение:

   macOS:

   ```bash
   ./venv/bin/python main.py
   ```

   Windows PowerShell:

   ```powershell
   .\venv\Scripts\python.exe main.py
   ```

3. Убедитесь, что окно открылось. В настройках проверьте OCR `Русский`,
   включите сохранение Word и дешифратора, а сохранение PDF оставьте
   выключенным для быстрого прогона.
4. В **Обезличивание** выберите через диалог два файла (DOCX и XLSX), затем
   запустите обработку. В результате должны появиться файлы с суффиксом
   `_cleaned` и по дешифратору рядом с каждым исходным файлом.
5. Для папочного режима нажмите **Выбрать папку** в блоке «Обезличить папку
   целиком». Укажите папку с тестовыми DOCX/XLSX/PDF. Обработка начинается
   автоматически, исходники не изменяются, а результаты и JSON-дешифраторы
   должны появиться в подпапке `Обезличенные документы`, а общий JSON-
   дешифратор — в корне выбранной папки. В интерфейсе должен отображаться
   полный путь этой подпапки. Вложенная папка результатов не должна
   обрабатываться повторно при повторном запуске.
6. Откройте обезличенные документы. Исходные ФИО не должны встречаться;
   одинаковая сущность в обоих файлах должна иметь один и тот же ID, например
   `[ФИО_1]`. В таблице подпись `ФИО` должна остаться подписью, а не замениться.
7. Для проверки автономного восстановления создайте рядом с папкой исходных
   документов отдельный файл анализа/иска с плейсхолдерами, например
   `case/analysis/позиция.docx`. Перейдите на **Восстановление**, выберите этот
   файл и оставьте переключатель **Автопоиск рядом и выше** включённым. JSON
   можно не выбирать: программа должна искать подходящий дешифратор в папке
   документа, затем в её родительских папках. В результате должен появиться
   `_восстановлено.docx` или `_восстановлено.xlsx` с исходными значениями.
8. Если автопоиск выключен, выберите JSON вручную; приложение не должно
   использовать старый дешифратор от предыдущего задания.
9. Откройте модальные окна списков и плейсхолдеров, закройте их,
   переключитесь между вкладками. Ни одно окно не должно зависать; отмена
   системного диалога не должна запускать обработку.

## Безопасная проверка Qwen

Автоматические тесты используют локальный fake backend и никогда не скачивают
веса. Для обычной проверки достаточно убедиться, что настройка сохраняется, а
основной сценарий обработки не меняется.

Если Qwen включается вручную, используйте только обезличенный тестовый файл и
параметр `local_files_only`, когда модель уже находится в локальном кэше.
Первое включение официальной модели может потребовать большой загрузки — это
не является частью CI и не нужно для прохождения тестов. При ошибке загрузки,
нарушении порядка плейсхолдеров, изменении чисел или чрезмерной правке должен
остаться исходный уже обезличенный текст.

## Что считать ошибкой

- Окно запускается, но фильтр диалога не соответствует выбранному типу файла.
- В пачке одинаковое лицо получает разные IDs или дешифраторы различаются.
- В очищенном файле остались исходные ФИО/контакты.
- Метка таблицы заменена вместе со значением или нарушилась структура таблицы.
- Восстановление меняет только часть документа либо не создаёт результат.
- Папочный режим изменяет исходный документ, кладёт результат вне подпапки
  `Обезличенные документы` или повторно обрабатывает собственные результаты.
- При восстановлении выбран не тот JSON из другого задания либо автопоиск не
  поднимается к родительской папке.
- Qwen получает исходные значения, меняет токены/числа или при недоступной
  модели приложение падает вместо безопасного no-op.
