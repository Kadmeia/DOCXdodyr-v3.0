> Актуализация решений владельца 2026-09-16: текущая подготовка сосредоточена на стабильности macOS; Windows проверяется отдельной будущей инструкцией `1/WINDOWS_FOLLOWUP_INSTRUCTIONS_2026-09-16.md`. Интеграции с Gemini/Google AI API в продукте не будет; связанные ключи и материалы не должны попасть в публичную Git-историю или бинарники. Распространение планируется через GitHub Releases и ручную публикацию владельцем идентичных готовых desktop-файлов в Telegram-канале. Проверенные hashes и версии должны совпадать. Ранние версии/минимумы ОС и допущения о подписи ниже — исторические решения; текущие подтверждённые требования и ограничения см. `1/NEXT_SESSION_PROMPT_MACOS_2026-09-16.md` и `1/SESSION_SUMMARY_2026-09-16.md`.

## 1. Продукт и позиционирование
- **Название**: DOCXдодыр
- **Текущая целевая версия**: 2.2.0 (планируется синхронизация версий ядра, UI и пакетов)
- **Назначение**: Локальное desktop-приложение для интеллектуального обезличивания, маскирования персональных данных (ПДн), очистки метаданных и правового анализа документов (DOCX, XLSX, текстовых и скан-PDF) для macOS и Windows.
- **Модель лицензирования**: **Freeware** (бесплатное проприетарное десктопное ПО с пользовательским лицензионным соглашением EULA).
  - Бинарные сборки (.app/DMG для macOS, Inno Setup installer для Windows) распространяются бесплатно.
  - Код ядра защищён от несанкционированной перепродажи, коммерческого ребрендинга и закрытия третьими лицами без согласия автора.
  - Лингвистический картридж `pullenti_legal` публикуется как отдельная библиотека под открытой лицензией MIT.
  - В дистрибутив включаются `EULA.txt` (или `LICENSE_FREEWARE.md`), `PRIVACY_POLICY.md` и `THIRD_PARTY_NOTICES.md`.
  - ADR: [docs/adr/0001-licensing-model.md](docs/adr/0001-licensing-model.md).

## 2. Глоссарий и термины
- **Дешифратор (`дешифратор.json`)**: Защищённая локальная таблица соответствия реальных сущностей (ФИО, адреса, номера счетов) и сгенерированных плейсхолдеров (`[ФИО_1]`, `[Адрес_1]`), формируемая строго на машине пользователя.
- **Плейсхолдер**: Стандартизированная маска замены сущности с сохранением юридического контекста и префиксов должностей (например, `Генерального директора [ФИО_1]`).
- **Сквозной реестр пачки**: Механизм единого сопоставления сущностей между несколькими файлами в рамках одного пакета документов.
- **Пакетный/папочный режим**: Рекурсивная потоковая обработка директорий с контролем целостности, manifest и hash-суммами.
- **Gold Standard (Эталонное обезличивание)**: Проверенная эталонная разметка, используемая для валидации качества и доработки алгоритмов.

## 3. Зафиксированные решения Grill-сессии (Этап 00)
1. **Лицензирование**: Freeware с EULA; картридж `pullenti_legal` — MIT (ADR 0001).
2. **Состав бесплатного ядра**: Полный локальный функционал без ограничений (ADR 0002).
   - Все локальные возможности (обработка DOCX, XLSX, текстовых и скан-PDF/OCR, пакетный режим папок, сквозной дешифратор и восстановление, аудит скрытых метаданных, ручная проверка Review, списки исключений и замен) полностью бесплатны для пользователя.
   - Никаких искусственных ограничений по объёму, страницам, файлам или водяных знаков в публичной версии нет.
   - Монетизация/поддержка: исключительно добровольные пожертвования (донаты через модальное окно «Поддержать автора»).
3. **Политика локальной обработки**: приложение работает локально и офлайн без интеграций с внешними нейросетевыми API; опциональная модель Qwen также выполняется локально.
4. **Поддерживаемые платформы и минимальные версии ОС** (ADR 0004):
   - **macOS**: macOS 12.0 (Monterey) и новее. Архитектуры: Apple Silicon (`arm64`) и Intel (`x86_64`). Обеспечивает нативный русский OCR через Apple Vision Framework и системный WKWebView.
   - **Windows**: Windows 10 (версия 1809+, 64-бит) и Windows 11 (64-бит). Архитектура: `x86_64`. Рендеринг через Microsoft Edge WebView2.
5. **Каналы распространения** (ADR 0005):
   - Основной официальный канал — **GitHub Releases** в репозитории проекта.
   - Пользователям предоставляются готовые бинарные сборки: `.dmg` для macOS (отдельно `arm64` и `x86_64`), `.exe` установщик (Inno Setup) для Windows, сопровождаемые файлом контрольных сумм (`SHA256SUMS.txt`), SBOM, Release Notes и инструкциями по установке.
   - Магазины приложений (Mac App Store / Microsoft Store) исключены для версии 2.2 во избежание ограничений App Sandbox на работу с произвольными папками файловой системы.
6. **Политика подписи кода (Code Signing)** (ADR 0006):
   - Архитектура сборочных скриптов должна штатно поддерживать подпись и нотаризацию при передаче секретов окружения (Apple Developer ID / Windows Authenticode).
   - Для начального публичного выпуска v2.2 платные платные сертификаты не являются обязательным блокирующим условием: допускается распространение ad-hoc подписанных `.app` (macOS) и стандартного неподписанного инсталлятора (Windows).
   - В релизную документацию и страницу GitHub Releases включается наглядная инструкция по первому запуску (macOS: клик правой кнопкой мыши -> «Открыть», Windows: клик «Подробнее» -> «Выполнить в любом случае»).
7. **Поставка локальной модели Qwen (Model Manager)** (ADR 0007):
   - Базовые релизные установщики (.dmg и Setup.exe) формируются как лёгкие компактные дистрибутивы (~150–250 МБ) без включения 1.7 ГБ весов нейросети.
   - Базовое ядро (Pullenti, OCR, DOCX, XLSX, аудит) полностью работоспособно офлайн без модели.
   - Для расширенного грамматического согласования текста в UI реализуется Model Manager:
     - Опциональная загрузка модели по прямому согласию пользователя с отображением размера (~1.75 ГБ), индикатором прогресса и проверкой SHA-256;
     - Офлайн-импорт готового zip-бандла (`qwen3.5-0.8b.bundle.zip`) для изолированных рабочих мест без интернета;
     - Модель и runtime-кэш размещаются в каталоге данных пользователя (`platformdirs.user_data_dir`).
     - Повреждённая или отсутствующая модель приводит к корректному no-op без сбоя приложения.
8. **Политика обновлений и технической поддержки** (ADR 0008):
   - Для версии 2.2 принято **ручное обновление через GitHub Releases**: пользователи скачивают новый DMG/установщик поверх установленной версии.
   - Пользовательские конфигурации, ключи в Keychain/Credential Manager, модели и дешифраторы хранятся в системных путях пользователя (`platformdirs`) и сохраняются при обновлении бинарников приложения.
   - Техническая поддержка и регистрация инцидентов/предложений осуществляются через **GitHub Issues** с шаблонами сообщений, исключающими ввод персональных данных и конфиденциального текста.
   - Автоматический бесшовный updater (Sparkle/WinSparkle) рассматривается как отдельная задача для будущих версий после стабилизации цифровой подписи.
