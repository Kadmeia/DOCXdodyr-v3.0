# Проверка папки перед GitHub

Исходники размещаются в папке `DOCXdodyr 3.0`. Старый каталог и его `.git`
содержат тестовые документы и не должны использоваться как источник истории
для публичного репозитория. Создавайте новый репозиторий из этой чистой папки.

## Порядок действий

1. Проверьте, что в папке нет реальных корпусов, артефактов обработки и Office/PDF
   документов: `python3.11 scripts/check_public_tree.py`.
   Дополнительно запустите `python scripts/scan_release_sources.py --output
   /tmp/docxdodyr-source-scan.json` и изучите отчёт: бинарные файлы и большие
   тексты не проверяются содержательно. Отдельно просмотрите адреса электронной
   почты и реквизиты в индексируемых `.py`, `.js`, `.html`, `.json` и `.md`,
   особенно в тестах и примерах. CI останавливается на найденных шаблонах
   учётных данных, но не удостоверяет отсутствие персональных данных.
2. Проверьте синтаксис: `python3.11 -m compileall -q .`.
3. Установите зависимости в отдельное окружение и запустите тесты:
   `python -m pytest -q`. На машине без GUI и моделей часть тестов пропускается;
   оставшиеся ошибки нужно оценить до публикации.
4. Создайте синтетические документы только при необходимости ручных проверок:
   `python tests/create_test_files.py` и `python tests/generate_mock_data.py`.
   После проверки удалите созданные `tests/test_data/`, `tests/source_files/`
   и `tests/output_files/` и снова запустите пункт 1.
5. Перед отправкой на GitHub проверьте список индексируемых файлов командой
   `git ls-files` и убедитесь, что там нет документов пользователей,
   локальных настроек, моделей и выходов обработки. Не используйте старую
   историю Git: удалённые из рабочего дерева файлы в ней сохраняются.

Эта проверка обнаруживает известные каталоги и расширения, но не заменяет
ручной осмотр текстов, которые будут опубликованы.
