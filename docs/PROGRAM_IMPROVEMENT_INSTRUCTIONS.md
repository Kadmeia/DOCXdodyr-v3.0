# Инструкция по улучшению DOCXдодыр

Дата ревизии: 24 августа 2026 года.

## Архитектурные границы

1. Pullenti и его юридический модуль — единственный источник сущностей и их
   позиций. Форматные идентификаторы допускается распознавать внутри модуля
   Pullenti строгими шаблонами, контрольными суммами и семантическими метками.
2. Регулярные выражения не должны самостоятельно менять документ после
   Pullenti. Они являются внутренней частью распознавателя номеров, а не вторым
   независимым обезличивателем.
3. Qwen получает только уже обезличенный текст. Модель не ищет персональные
   данные, не назначает ID, не читает дешифратор и не восстанавливает значения.
4. Один запуск пачки использует единый реестр сущностей. Одинаковое лицо и его
   падежные формы получают один ID во всех выбранных файлах.
5. Метка таблицы служит контекстом для значения в соседней ячейке, но сама не
   подменяется. Координаты найденной сущности всегда проецируются обратно в
   исходную ячейку.

## Выполненный этап

- Добавлены юридические сущности, строгие проверки идентификаторов, контекст
  таблиц и единые ID пачки.
- Реализован безопасный Qwen 3.5 0.8B: ленивая загрузка, защита плейсхолдеров,
  запрет изменения чисел и безопасный откат к исходному обезличенному тексту.
- OCR разделён по ОС: Apple Vision на macOS, Tesseract и PaddleOCR-fallback на
  Windows/Linux; Tesseract не используется активной программой.
- Короткий PDF с пригодным текстовым слоем больше не отправляется в OCR.
- При runtime-сбое OCR программа пробует другой установленный движок.
- Строковые значения `false` и `0` больше не включают Qwen ошибочно.
- Сохранены крайние пробелы абзацев, чтобы позиции Pullenti совпадали с
  записываемым текстом.
- Tailwind собран в локальный CSS: основной интерфейс запускается без CDN и
  не требует интернет-соединения для отображения.
- Добавлены сценарные тесты запуска, пачки DOCX/XLSX, таблиц, дешифратора,
  восстановления и безопасного Qwen.

### Реализовано в backend-блоке контроля приватности

- `privacy_audit.py` формирует локальный сертификат с SHA-256 входного и
  выходного файла, UTC-временем, версией правил и числовыми агрегатами. Исходные
  значения сущностей и дешифратор в сертификат не попадают.
- `ReviewQueue` хранит находки с типом, координатой, плейсхолдером,
  confidence и обезличенным контекстом; доступные решения — принять,
  отклонить или пропустить. Поля исходного значения намеренно отсутствуют.
- Очистка Office-пакетов удаляет core/app/custom properties и thumbnail, а
  очистка PDF — Info/XMP, если в файле нет шифрования, формы, вложений или
  цифровой подписи. В рискованных случаях сохраняется копия без перепаковки и
  записывается причина пропуска.
- `hidden_data.py` проверяет комментарии, сноски, скрытый текст, исправления,
  Office-вложения, макросы/custom XML, PDF-аннотации, формы, JavaScript,
  вложения, подписи и XMP/EXIF. Комментарии, исправления, вложения, аннотации
  и метаданные очищаются автоматически; сноски и скрытый текст требуют
  отдельного явного разрешения как юридически значимое содержимое.
- Очередь подключена к экрану ручной проверки: после обработки пользователь
  видит тип, плейсхолдер, координату, confidence и только обезличенный контекст,
  затем может принять, отклонить или пропустить находку.
- Для каждого реально созданного результата автоматически очищаются безопасные
  метаданные и формируется соседний `*.audit.json`. Отладочные журналы не
  включают исходные значения сущностей.
- Папочный режим рекурсивно обрабатывает поддерживаемые документы, сохраняет
  структуру в подпапке `Обезличенные документы`, использует единый реестр ID и
  пишет один корневой дешифратор. Восстановление умеет ограниченно искать его
  в текущей и родительских папках.
- Решение «отклонить» атомарно пересобирает DOCX/XLSX/PDF, включая
  колонтитулы, сноски, концевые сноски и комментарии DOCX, и возвращает только
  выбранное вхождение. Приватный контекст между перезапусками хранится только
  в зашифрованном vault с ключом системного хранилища; plaintext-fallback
  запрещён. Исходник не передаётся в JS/логи/audit.
- Необратимый PDF включается отдельным переключателем: каждая страница
  растрируется, текстовый слой, аннотации, вложения и метаданные не переносятся.
- OCR возвращает единый `OCRDocumentResult`: текст, номер страницы,
  нормализованный bbox и confidence независимо от Apple Vision,
  Tesseract или PaddleOCR. Старый текстовый API сохранён.

## Оставшийся приоритетный этап

Технический контур разметки и метрик уже реализован: versioned split,
precision/recall/F1 по типам сущностей и отдельно по text/table/OCR, очередь
ручной проверки и учёт пропущенных spans. Экран проверки получил фильтры,
массовое принятие, переходы к DOCX/XLSX-координатам и подсветку настоящих
OCR-bbox. Pullenti-картридж собирается как отдельные wheel и sdist; Qwen имеет
проверяемый offline-комплект и реальный smoke-тест.

Остаётся не программная, а редакционная работа: люди-разметчики должны
подтвердить минимум 200 реальных примеров каждого из 90 типов. Автоматическая
предразметка Luna имеет статус `model_reviewed` и намеренно не считается gold.
В текущем локальном корпусе 47 522 кандидата из 500 документов, но они покрывают
только 12 типов; для остальных нужны дополнительные открытые источники с
проверенной лицензией и ручное подтверждение. Публикация пакета в PyPI и PR в
официальный Pullenti также являются внешними release-действиями, а не
незавершённым кодом приложения.

## Критерии приёмки каждого изменения

- Ни один исходный идентификатор не передаётся внешней или локальной LLM.
- Плейсхолдеры и фактические числа не меняются Qwen; при сомнении применяется
  no-op.
- Одинаковые сущности получают одинаковые ID в пачке.
- Табличная структура, заголовки, колонтитулы и крайние пробелы не повреждаются.
- Для каждого исправленного дефекта есть регрессионный тест.
- Полный запуск `pytest` заканчивается `0 failed`, а ключевые действия
  дополнительно проверяются в запущенном интерфейсе.
