Руководство
# Руководство пользователя DOCXдодыр 3.0.0

Ревизия 11 сентября 2026. Development-сборка; production-приёмка трёх платформ ещё не завершена.

## Первый запуск

Выберите сборку для своей ОС и процессора. На macOS приложение переносится в Applications; Windows использует per-user installer и WebView2. Публично доверенной подписанной сборки эта ревизия не обещает. Начните с синтетического документа. В меню «Помощь» сверяйте версию, архитектуру и каталог данных. Основная обработка локальна; Qwen устанавливается отдельно и отключён по умолчанию.

## Главное окно и результат

Вкладки разделяют обезличивание и восстановление. Нажатие области выбора открывает системный диалог; перетаскивание передаёт пути bridge. Выберите файлы или папку, настройте типы замен, затем запускайте действие. Счётчик и полоса отражают ход операции. «Отмена» запрашивает остановку worker; дождитесь завершения перед повторным запуском. Открытие папки результата показывает фактические выходные копии. Не передавайте всю папку автоматически: в ней могут находиться исходники и дешифраторы.

«Настройка обезличивания» открывает категории и образцы плейсхолдеров. Поиск фильтрует категории, выбор слева показывает описание справа, выбор всех/снятие всех меняет набор типов, переключатель скобок меняет представление токенов. Сохраните изменения явно. «Исключения и замены» редактирует локальные списки; добавленные исходные значения являются чувствительными данными. Закрытие модального окна и Escape возвращают к работе; проверяйте, были ли изменения сохранены.

«Распознавание PDF» запускает OCR; извлечённый текст сам по себе не означает обезличивание. Язык OCR задаётся отдельно. DOCX/XLSX обрабатываются структурно; PDF может использовать извлечение текста и распознавание. Сложная вёрстка, изображения с текстом, формулы, макросы и вложения требуют ручной проверки. Файлы с защитой или повреждениями могут быть отклонены. Единого гарантированного предела страниц/размера для всех форматов нет: учитывайте доступные RAM и диск, большие пакеты делите.

## Проверка и скрытые данные

Экран проверки фильтруется по типу, документу, статусу и минимальной уверенности. Preview показывает исходный контекст локально. Accepted подтверждает решение, rejected отклоняет, skipped откладывает рассмотрение; изменение статуса не следует считать автоматическим безопасным пересозданием всех выходных файлов. Для отклонённых находок предусмотрено отдельное пересоздание. Массовое принятие действует на фильтр: проверьте его перед нажатием. «Очистить список» удаляет очередь проверки, а не исходные файлы. Отдельное окно/разворачивание меняют представление.

Инспекция скрытых данных сначала показывает обнаруженные части. Выбор политики и подтверждение удаления создают копию; удалённые вложения, комментарии и макросы нельзя восстановить дешифратором. Цифровая подпись исходника может стать недействительной после изменения. Наличие сохранённой подписи не подтверждает её криптографическую действительность.

## Восстановление и Qwen

Выберите обезличенный документ и соответствующий JSON. При включённом автопоиске программа проверяет соседние и родительские папки, binding/manifest. Ошибка соответствия означает остановку: не редактируйте hashes/IDs для обхода. Дешифратор содержит исходные значения и не равнозначен зашифрованному vault. Храните его отдельно с ограниченным доступом.

Qwen корректирует формы текста локально; не требуется базовой обработке. Загрузка запрашивает согласие и место на диске; доступен offline bundle, проверка целостности, отмена и удаление. Веса и все служебные файлы проверяются по закреплённым размерам и SHA-256 на конкретной ревизии модели. После установки включение модели — отдельная настройка. Полная проверка реальной Qwen в данной ревизии не выполнена.

## Настройки по умолчанию

Ниже значения из settings.example.json; пользовательские настройки и миграция могут отличаться. Посмотрите фактические переключатели перед обработкой.

| Поле | Пример по умолчанию | Смысл |
|---|---|---|
| save_original | true | Сохранять исходную копию в комплекте; не передавать её третьим лицам |
| save_pdf | false | Дополнительный PDF; доступность зависит от конвертера |
| irreversible_pdf | false | Растеризованный выход; видимые данные всё равно требуют обезличивания |
| save_decoder | false | Включите, если требуется последующее восстановление |
| auto_decoder | true | Поиск дешифратора рядом с документом |
| open_output_folder | true | Открывать папку результата |
| qwen_enabled | false | Использовать установленную локальную модель |
| ocr_lang | rus+eng | Основные языки OCR |
| bracket_type | square | Квадратные скобки плейсхолдеров |
| enabled_placeholders | список типов | Отмеченные категории сущностей |
| hidden_data_policy | по типам | Удаление/обезличивание/сохранение скрытых частей |

Политика скрытых данных в примере удаляет comments, tracked_changes, embedded_objects/files, annotations, acroform, javascript, macros, custom_xml, external_links и свойства; footnotes/endnotes/hidden_text обезличивает; digital_signature/encrypted_pdf сохраняет. Последние два значения не являются обещанием безопасного редактирования защищённого PDF.

## Чего приложение не делает

Не гарантирует абсолютную полноту обезличивания, не восстанавливает удалённые структурные части, не заменяет юридическую/ИБ-проверку, не превращает любой скан в точную копию исходной вёрстки. Не объявляет Windows ARM64 нативно поддержанным. Обновление и удаление данных выполняйте по отдельным инструкциям; автоматического безопасного стирания всех копий нет.

Полный реестр элементов: [UI_MAP](UI_MAP.md). Сценарии: [WORKFLOWS](WORKFLOWS.md). Ошибки: [TROUBLESHOOTING](TROUBLESHOOTING.md). Данные: [DATA_RETENTION_AND_DELETION](DATA_RETENTION_AND_DELETION.md).

# Рабочие сценарии DOCXдодыр 3.0.0

Ревизия 11 сентября 2026. Это процедуры приёмки на синтетических данных; они не означают, что каждый сценарий уже пройден на всех платформах. Windows/Intel и clean-machine результаты пока не подтверждены.

## Один DOCX

Цель: один docx.

Исходные условия и тестовые данные: Синтетический DOCX с именем «Тестовый Персонаж» и маркером TEST-001.

Действия: Выберите документ на вкладке обезличивания; включите нужные категории и сохранение дешифратора, если нужно восстановление; запустите обработку.

Ожидаемый экран: завершение операции либо понятная ошибка; проверьте фактический статус перед открытием результата.

Созданные файлы: Новая обезличенная копия и, при включённой опции, JSON.

Контроль результата: Проверьте текст, таблицы, колонтитулы и скрытые части.

Типичные ошибки и безопасный откат: Неверная категория: скорректируйте настройки и повторите в новой папке. Исходный синтетический файл сохраните; повторную обработку выполняйте в новой папке.

Удаление данных
# Хранение и удаление данных

Ревизия 11 сентября 2026, версия 3.0.0. Источник путей: `app_paths.py`; фактический путь показан во встроенной справке. Переменные DOCXDODYR_DATA_DIR, DOCXDODYR_USER_DATA_DIR, DOCXDODYR_CONFIG_DIR, DOCXDODYR_CACHE_DIR и DOCXDODYR_LOG_DIR могут переопределить каталоги.

| Данные | macOS по умолчанию | Windows по умолчанию |
|---|---|---|
| Настройки, списки, очередь, vault, recovery, models | ~/Library/Application Support/DOCXdodyr | %LOCALAPPDATA%\DOCXdodyr |
| Кэш | ~/Library/Caches/DOCXdodyr | %LOCALAPPDATA%\DOCXdodyr\Cache |
| Журнал | ~/Library/Logs/DOCXdodyr | %LOCALAPPDATA%\DOCXdodyr\Logs |

`settings.json` хранит настройки, `Исключения.txt` и `Замены.txt` — пользовательские списки. Они могут содержать исходные значения. `review_queue.json` — очередь решений; `.review_context.enc` — зашифрованный контекст. Ключ vault находится в системном keyring. `recovery` хранит контрольные точки; `models` — необязательные веса Qwen. Системный каталог временных файлов и временные папки обработки также могут содержать промежуточные документы. Выходные файлы, исходники, manifests, дешифраторы и их резервные копии лежат в выбранных пользователем каталогах, а не обязательно рядом с настройками.

Срок хранения задаёт пользователь: автоматическое удаление всех данных по календарному сроку не реализовано. После сбоя не удаляйте временные файлы до проверки результата восстановления.

Для удаления: закройте приложение, решите, нужны ли сохранённые результаты и дешифраторы, затем удалите соответствующие каталоги данных, настроек, кэша и журналов через Finder или Проводник. Удалите модель кнопкой управления Qwen либо вместе с её каталогом. Отдельно проверьте папки обработанных комплектов, корзину, резервные копии и синхронизируемые облачные папки. Удаление приложения через корзину или деинсталлятор не означает удаления пользовательских данных. Ключ vault удаляйте через системное хранилище только после отказа от восстановления всех связанных контекстов. Сервис/учётную запись сверяйте с `review_context.py`, не удаляйте чужие ключи.

Удаление файлов не гарантирует физическое стирание SSD или резервных копий. Для носителей с чувствительными данными применяйте установленную в организации процедуру уничтожения.

# ПОЛИТИКА КОНФИДЕНЦИАЛЬНОСТИ
## Десктопное приложение «DOCXдодыр» (Версия 3.0)

Дата вступления в силу: 3 сентября 2026 г.

---

### 1. ОСНОВОПОЛАГАЮЩИЙ ПРИНЦИП: LOCAL-FIRST

1.1. Главная цель «DOCXдодыр» — обеспечить максимальную безопасность и защиту персональных данных (ПДн) и коммерческой тайны. Приложение спроектировано в архитектуре **Local-First** (полная локальная автономность).  
1.2. Все основные операции:
- чтение и синтаксический разбор документов (DOCX, XLSX, PDF);
- оптическое распознавание текста сканов (OCR через системный Apple Vision Framework на macOS или локально установленный Tesseract на Windows);
- извлечение именованных сущностей (NER) и юридических реквизитов через локальные правила Pullenti;
- генерация плейсхолдеров и ведение чувствительной таблицы соответствия (`дешифратор.json`), которую нельзя считать зашифрованной;
- очистка скрытых метаданных и ревизий документов,
**выполняются строго локально на оборудовании пользователя без передачи информации в сеть Интернет**.

---

### 2. ОТСУТСТВИЕ СКРЫТОЙ ТЕЛЕМЕТРИИ И АНАЛИТИКИ

2.1. Приложение **не содержит** скрытых трекеров, счетчиков посещаемости, модулей сбора поведенческой телеметрии или фоновых сетевых запросов.  
2.1а. По явному действию пользователя загрузчик Qwen обращается к Hugging Face и разрешённым HTTPS-хранилищам весов; ссылки поддержки/автора открывают внешний браузер. Эти сервисы получают обычные сетевые метаданные запроса. Базовая обработка не требует загрузки модели. Просмотр исходного контекста ручной проверки показывает его в локальном WebView; это чувствительный экран, который нельзя публиковать.
2.2. При работе в базовом режиме приложение может эксплуатироваться на полностью изолированных рабочих станциях (Air-Gapped) без подключения к локальной сети или интернету.

---

### 3. ЛОКАЛЬНЫЕ МОДЕЛИ

3.1. Приложение не содержит интеграций с внешними нейросетевыми API и не отправляет документы в облачные модели.
3.2. Опциональная модель Qwen устанавливается и выполняется локально на компьютере Пользователя.

### 4. ХРАНЕНИЕ ПОЛЬЗОВАТЕЛЬСКИХ ДАННЫХ И СОСТОЯНИЯ

4.1. В соответствии со стандартами операционных систем (`platformdirs`) рабочие файлы приложения размещаются в изолированных пользовательских каталогах:
- **macOS**: `~/Library/Application Support/DOCXdodyr` (настройки и данные), `~/Library/Caches/DOCXdodyr` (кэш), `~/Library/Logs/DOCXdodyr` (журналы);
- **Windows**: `%LOCALAPPDATA%\DOCXdodyr` (настройки и данные), `%LOCALAPPDATA%\DOCXdodyr\Cache` (кэш), `%LOCALAPPDATA%\DOCXdodyr\Logs` (журналы).  
4.2. Все файлы состояния (`settings.json`, очередь проверки `review_queue.json`) записываются атомарно с ограничением прав доступа только для текущего пользователя (`0o600`).  
4.3. Контекст ручного ревью для защиты от утечек шифруется криптографическим алгоритмом Fernet (AES-128-CBC с HMAC-SHA256) и сохраняется в файле `.review_context.enc`.  
4.4. Пользователь в любой момент может удалить все сохраненные настройки, кэш и историю, удалив указанные выше пользовательские каталоги.

Ограничения
# Ограничения DOCXдодыр

Проект документа для версии 3.0.0, 11 сентября 2026. Требует юридической проверки перед публикацией.

Автоматическое распознавание допускает пропуски (false negative) и лишние замены (false positive). OCR зависит от качества скана и языка. Проверьте основной текст, таблицы, колонтитулы, изображения, скрытые части и свойства каждой выходной копии. Программа не подтверждает соответствие требованиям законодательства и не заменяет профессиональную проверку.

Растеризованный PDF лишается исходного текстового слоя, но видимый текст на странице можно снова прочитать или распознать OCR. Поэтому растеризация сама по себе не обезличивает страницу. Дешифратор и исходник остаются чувствительными данными; не передавайте их вместе с обезличенной копией. Изменение подписанного документа может нарушить действительность цифровой подписи.

Применение программы в оплачиваемой профессиональной работе и коммерческое использование результатов разрешены бесплатно. Ограничения распространения самой программы описаны в [EULA](EULA.md). Ничто в этом документе не исключает ответственность, которую нельзя исключить по применимому праву.
